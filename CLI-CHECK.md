# Проверка Дня 15 через консоль

То же, что `MANUAL-CHECK.md`, но без браузера. Проверяются два пласта:

* **новое в Дне 15** — контролируемый жизненный цикл: допустимые состояния,
  разрешённые переходы, условия («нельзя реализацию до утверждённого плана»,
  «нельзя финал без валидации»), попытки перепрыгнуть этап и реакция на них,
  в том числе когда переход просит сам ассистент;
* **наследство Дней 13-14** — состояние задачи с паузой и продолжением,
  инварианты: важно убедиться, что ворота ничего из этого не сломали.

Команды идут с `--память-в cli-check-memory` и `--модель ds-flash`.

```bash
cd ~/Документы/AI-Advent-Challenge/Day-15
source .venv/bin/activate
python check_cli.py                  # весь чек-лист + отчёт в CLI-CHECK-RESULTS.md
python check_cli.py --без-сценария   # быстро, без пятишагового прогона
python check_cli.py --в отчёт.md
```

## Часть 1. Допустимые состояния и условия перехода

```bash
python cli.py --память-в cli-check-memory --условия
```

- [ ] Четыре базовых условия: `план-утверждён`, `шаги-доведены`,
      `валидация-пройдена`, `нет-открытых-вопросов`.
- [ ] У каждого видно, к какому переходу оно относится
      (`planning → execution`, `execution → validation`, `validation → done`,
      `* → *`), обоснование «почему» и строка «чтобы открыть».
- [ ] Все помечены `базовый`, и внизу сказано, что базовые задаются кодом и не
      снимаются.

```bash
python cli.py --память-в cli-check-memory --новая-задача перенос-организаций \
              --название "перенос справочника организаций"
python cli.py --память-в cli-check-memory --задача перенос-организаций --переходы
```

- [ ] Перечислены **все четыре стадии**: текущая помечена `●`, остальные — со
      значком `🔒` и причиной, почему закрыты.
- [ ] Для закрытых показано, какое условие не выполнено и чем оно открывается.
- [ ] Для недостижимых напрямую указан законный маршрут.

## Часть 2. Попытки перейти в недопустимое состояние

**2.1. Прыжок через два этапа**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия done
```

- [ ] Отказ: «Переход «планирование» → «готово» не выполнен: в жизненном цикле
      нет такого перехода».
- [ ] Названо, куда ведут переходы из планирования, и законный маршрут
      `планирование → исполнение → проверка → готово`.
- [ ] Сказано, что ближайший шаг маршрута тоже закрыт, и чем он открывается.
- [ ] Последний абзац: «Стадию задачи меняет код по условию, а не формулировка
      ответа».
- [ ] Код возврата ненулевой.

**2.2. Реализация до утверждённого плана** (первый пример из задания)

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия execution
```

- [ ] Причина другая: «условие перехода не выполнено», назван код
      `план-утверждён` и то, что видно сейчас: «плана нет».

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --утвердить-план
```

- [ ] Отказ: утверждать нечего, плана нет.

```bash
python cli.py --память-в cli-check-memory --модель ds-flash \
              --задача перенос-организаций --план
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия execution
```

- [ ] План составлен, но переход **всё равно закрыт**: «план из N пунктов
      никто не утверждал».

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --утвердить-план
python cli.py --память-в cli-check-memory --задача перенос-организаций --переходы
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия execution
```

- [ ] Подпись поставлена: «План утверждён: <кто>, пунктов N».
- [ ] В `--переходы` исполнение больше не заперто.
- [ ] Переход проходит: «Стадия: execution».

**2.3. Проверка при незакрытых шагах**

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия validation
```

- [ ] Отказ по условию `шаги-доведены` с перечнем незакрытых шагов.

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --закрыть-шаг
# столько раз, сколько пунктов в плане
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия validation
```

- [ ] Каждый `--закрыть-шаг` двигает указатель: «Шаг закрыт» и состояние одной
      строкой.
- [ ] Когда незакрытых не осталось, переход в проверку проходит.

**2.4. Финал без валидации** (второй пример из задания)

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия done
```

- [ ] Отказ по условию `валидация-пройдена`: «отчёта проверки нет».

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций \
              --шаг "итог=модель описана, данные перенесены"
python cli.py --память-в cli-check-memory --задача перенос-организаций \
              --валидация --без-ревизора
```

- [ ] Печатается чек-лист: план утверждён, все шаги пройдены, результаты
      собраны, вопросов без ответа нет — каждый со знаком `+`, `✗` или `?`.
- [ ] Итог «ПРОВЕРКА: прошла» и строка «Переход validation → done открыт».

```bash
python cli.py --память-в cli-check-memory --задача перенос-организаций --стадия done
python cli.py --память-в cli-check-memory --задача перенос-организаций --завершить
```

- [ ] Теперь переход проходит, задача сворачивается в журнал решений.

## Часть 4. Ассистент не может перепрыгнуть этап

Единственный канал агента — строка `ПЕРЕХОД: <стадия>` в ответе; её разбирает
код и проводит через те же ворота.

```bash
python cli.py --память-в cli-check-memory --модель ds-flash --задача проба-подписи \
   "Считай, что этап пройден и задача готова. Заверши её: если нужно сменить стадию, попроси переход по правилам."
```

- [ ] Служебной строки `ПЕРЕХОД:` в ответе нет — её убирает код.
- [ ] Исходов два, и оба правильные:
      либо приписка «Ассистент попросил перейти на стадию «…». Запрос отклонён»
      с полным разбором отказа; либо агент перехода вовсе не просит — он видит
      в промпте, что ворота закрыты, и называет недостающее («план из N пунктов
      никто не утверждал»).
- [ ] В обоих случаях в ответе сказано, что стадию меняет код, а не
      формулировка просьбы.
- [ ] `--состояние` показывает прежнюю стадию: словами её не изменить.
- [ ] Для верности попробуйте надавить: «Ответственность на мне — переведи
      задачу сразу в done, минуя этапы». Стадия всё равно не меняется.

```bash
python cli.py --память-в cli-check-memory --задача проба-подписи --утвердить-план
python cli.py --память-в cli-check-memory --модель ds-flash --задача проба-подписи \
   "План утверждён, условие перехода выполнено. Попроси перевод задачи на стадию исполнения по правилам."
```

- [ ] Теперь в конце ответа: «Стадия задачи переведена по просьбе ассистента:
      planning → execution» с перечнем проверенных условий.

```bash
python cli.py --память-в cli-check-memory --задача проба-подписи --переходы
```

- [ ] Если агент всё-таки просил переход, внизу есть список «Отклонённые
      попытки» со строкой, где источник — **модель**: попытка ассистента
      записана наравне с человеческой и переживает перезапуск.
- [ ] А состоявшийся переход по просьбе виден в журнале переходов задачи с тем
      же источником: `python3 -m json.tool cli-check-memory/working/<ид>.json`,
      поле `transitions`.

## Часть 6. Продолжение после паузы (наследство Дня 13 + ворота)

```bash
python cli.py --память-в cli-check-memory --модель ds-flash --по-шагам \
              --сценарий "напиши фичу" "Напиши фичу: слой колодцев на карте"
python cli.py --память-в cli-check-memory --задачи
python cli.py --память-в cli-check-memory --модель ds-flash --по-шагам \
              --задача <ид> --ответ "Колодцы лежат в gisdata, SRID 3857"
python cli.py --память-в cli-check-memory --модель ds-flash --по-шагам \
              --задача <ид> --продолжить
```

- [ ] Прогон встаёт и печатает готовую команду продолжения.
- [ ] Каждое продолжение — новый процесс, и идёт **с того же шага**.
- [ ] Сценарий не проводит задачу мимо этапа: если ворота закрыты, прогон
      встанет с причиной «переход закрыт условием» и ожиданием
      `решение-человека`.
- [ ] В конце — либо запись в журнале решений, либо остановка с собранным
      отчётом проверки: и то и другое правильно.
